# FlowPay — Database Design v1

## General Strategy

```text
Database            PostgreSQL
Schema migrations   Flyway
Internal PK         BIGINT GENERATED BY IDENTITY
Public ID           VARCHAR, unique, prefixed
Money               BIGINT minor units
Currency            CHAR(3)
Timestamp           TIMESTAMPTZ
Enums               VARCHAR
Optimistic lock     BIGINT version
```

Do not physically delete core financial records.

Do not use `ON DELETE CASCADE` for financial tables.

## Public ID Prefixes

```text
usr_   User

ptxn_  PaymentTransaction
```

## Tables

### users

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
email VARCHAR UNIQUE NOT NULL
password_hash VARCHAR NOT NULL
first_name VARCHAR NOT NULL
last_name VARCHAR NOT NULL
status VARCHAR NOT NULL
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
version BIGINT NOT NULL DEFAULT 0
```

### merchants

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
name VARCHAR NOT NULL
status VARCHAR NOT NULL
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
version BIGINT NOT NULL DEFAULT 0
```

### merchant_members

```text
merchant_id BIGINT NOT NULL FK -> merchants.id
user_id BIGINT NOT NULL FK -> users.id
role VARCHAR NOT NULL
created_at TIMESTAMPTZ NOT NULL
PRIMARY KEY (merchant_id, user_id)
```

### merchant_api_keys

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
merchant_id BIGINT NOT NULL FK -> merchants.id
name VARCHAR NOT NULL
key_prefix VARCHAR NOT NULL
key_hash VARCHAR NOT NULL
status VARCHAR NOT NULL
last_used_at TIMESTAMPTZ NULL
expires_at TIMESTAMPTZ NULL
revoked_at TIMESTAMPTZ NULL
created_at TIMESTAMPTZ NOT NULL
```

Indexes/constraints:

```text
UNIQUE(key_prefix)
INDEX(merchant_id, status)
```

### payment_intents

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
merchant_id BIGINT NOT NULL FK -> merchants.id
merchant_order_id VARCHAR NULL
description VARCHAR NULL
amount_minor BIGINT NOT NULL
currency CHAR(3) NOT NULL
status VARCHAR NOT NULL
refunded_amount_minor BIGINT NOT NULL DEFAULT 0
refund_reserved_minor BIGINT NOT NULL DEFAULT 0
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
version BIGINT NOT NULL DEFAULT 0
```

Constraints:

```text
amount_minor > 0
refunded_amount_minor >= 0
refund_reserved_minor >= 0
refunded_amount_minor + refund_reserved_minor <= amount_minor
```

Indexes:

```text
UNIQUE(public_id)
INDEX(merchant_id, created_at DESC)
INDEX(merchant_id, status, created_at DESC)
INDEX(merchant_id, merchant_order_id)
```

`merchant_order_id` is not globally unique and is not an idempotency mechanism.

### payment_transactions

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
payment_intent_id BIGINT NOT NULL FK -> payment_intents.id
attempt_no INTEGER NOT NULL
provider VARCHAR NOT NULL
provider_transaction_id VARCHAR NULL
status VARCHAR NOT NULL
failure_code VARCHAR NULL
failure_message VARCHAR NULL
started_at TIMESTAMPTZ NULL
completed_at TIMESTAMPTZ NULL
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
version BIGINT NOT NULL DEFAULT 0
```

Constraints/indexes:

```text
CHECK(attempt_no > 0)
UNIQUE(payment_intent_id, attempt_no)
INDEX(provider, provider_transaction_id)
```

Prefer a partial unique index for provider reference when provider semantics guarantee uniqueness:

```text
UNIQUE(provider, provider_transaction_id)
WHERE provider_transaction_id IS NOT NULL
```

### refunds

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
merchant_id BIGINT NOT NULL FK -> merchants.id
payment_intent_id BIGINT NOT NULL FK -> payment_intents.id
amount_minor BIGINT NOT NULL
currency CHAR(3) NOT NULL
status VARCHAR NOT NULL
reason VARCHAR NULL
provider_refund_id VARCHAR NULL
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
version BIGINT NOT NULL DEFAULT 0
```

Constraints/indexes:

```text
CHECK(amount_minor > 0)
INDEX(payment_intent_id, created_at)
INDEX(merchant_id, created_at DESC)
INDEX(merchant_id, status, created_at DESC)
```

### idempotency_records

```text
id BIGINT PK
merchant_id BIGINT NOT NULL
operation VARCHAR NOT NULL
idempotency_key VARCHAR NOT NULL
request_hash VARCHAR NOT NULL
status VARCHAR NOT NULL
resource_type VARCHAR NULL
resource_public_id VARCHAR NULL
http_status INTEGER NULL
response_payload JSONB NULL
created_at TIMESTAMPTZ NOT NULL
completed_at TIMESTAMPTZ NULL
expires_at TIMESTAMPTZ NOT NULL
```

Constraint:

```text
UNIQUE(merchant_id, operation, idempotency_key)
```

Statuses:

```text
PROCESSING
COMPLETED
FAILED
```

### ledger_accounts

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
account_code VARCHAR UNIQUE NOT NULL
account_type VARCHAR NOT NULL
owner_type VARCHAR NULL
owner_id BIGINT NULL
currency CHAR(3) NOT NULL
status VARCHAR NOT NULL
created_at TIMESTAMPTZ NOT NULL
```

Initial account concepts:

```text
CUSTOMER_CLEARING
MERCHANT_PAYABLE
FLOWPAY_FEE
REFUND_CLEARING
```

### ledger_transactions

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
posting_type VARCHAR NOT NULL
reference_type VARCHAR NOT NULL
reference_id VARCHAR NOT NULL
currency CHAR(3) NOT NULL
description VARCHAR NULL
occurred_at TIMESTAMPTZ NOT NULL
created_at TIMESTAMPTZ NOT NULL
```

Constraint:

```text
UNIQUE(posting_type, reference_type, reference_id)
```

This protects event-consumer idempotency for ledger posting.

### ledger_entries

```text
id BIGINT PK
ledger_transaction_id BIGINT NOT NULL FK -> ledger_transactions.id
ledger_account_id BIGINT NOT NULL FK -> ledger_accounts.id
entry_no INTEGER NOT NULL
direction VARCHAR NOT NULL
amount_minor BIGINT NOT NULL
created_at TIMESTAMPTZ NOT NULL
```

Constraints:

```text
CHECK(amount_minor > 0)
CHECK(direction IN ('DEBIT', 'CREDIT'))
UNIQUE(ledger_transaction_id, entry_no)
```

Cross-row debit=credit is enforced in domain/application logic and tests in v1.

### webhook_endpoints

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
merchant_id BIGINT NOT NULL FK -> merchants.id
url VARCHAR NOT NULL
secret_ciphertext TEXT NOT NULL
status VARCHAR NOT NULL
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
version BIGINT NOT NULL DEFAULT 0
```

Webhook signing secret must be encrypted, not hashed, because FlowPay needs the original secret to sign outbound messages.

### webhook_endpoint_events

```text
endpoint_id BIGINT NOT NULL FK -> webhook_endpoints.id
event_type VARCHAR NOT NULL
PRIMARY KEY(endpoint_id, event_type)
```

### webhook_events

```text
id BIGINT PK
public_id VARCHAR UNIQUE NOT NULL
event_type VARCHAR NOT NULL
resource_type VARCHAR NOT NULL
resource_id VARCHAR NOT NULL
payload JSONB NOT NULL
occurred_at TIMESTAMPTZ NOT NULL
created_at TIMESTAMPTZ NOT NULL
```

Webhook events are immutable.

### webhook_deliveries

```text
id BIGINT PK
webhook_event_id BIGINT NOT NULL FK -> webhook_events.id
webhook_endpoint_id BIGINT NOT NULL FK -> webhook_endpoints.id
status VARCHAR NOT NULL
attempt_count INTEGER NOT NULL DEFAULT 0
next_attempt_at TIMESTAMPTZ NULL
delivered_at TIMESTAMPTZ NULL
last_http_status INTEGER NULL
last_error TEXT NULL
created_at TIMESTAMPTZ NOT NULL
updated_at TIMESTAMPTZ NOT NULL
version BIGINT NOT NULL DEFAULT 0
```

Constraints/indexes:

```text
UNIQUE(webhook_event_id, webhook_endpoint_id)
INDEX(status, next_attempt_at)
```

Statuses:

```text
PENDING
DELIVERING
DELIVERED
RETRYING
DEAD
```

### webhook_delivery_attempts

```text
id BIGINT PK
delivery_id BIGINT NOT NULL FK -> webhook_deliveries.id
attempt_no INTEGER NOT NULL
started_at TIMESTAMPTZ NOT NULL
finished_at TIMESTAMPTZ NULL
http_status INTEGER NULL
duration_ms INTEGER NULL
error_message TEXT NULL
created_at TIMESTAMPTZ NOT NULL
```

Constraint:

```text
UNIQUE(delivery_id, attempt_no)
```

### outbox_events

```text
id BIGINT PK
event_id VARCHAR UNIQUE NOT NULL
aggregate_type VARCHAR NOT NULL
aggregate_id VARCHAR NOT NULL
event_type VARCHAR NOT NULL
payload JSONB NOT NULL
status VARCHAR NOT NULL
occurred_at TIMESTAMPTZ NOT NULL
available_at TIMESTAMPTZ NOT NULL
published_at TIMESTAMPTZ NULL
retry_count INTEGER NOT NULL DEFAULT 0
last_error TEXT NULL
created_at TIMESTAMPTZ NOT NULL
```

Index:

```text
INDEX(status, available_at)
```

Statuses:

```text
PENDING
PUBLISHED
FAILED
```
